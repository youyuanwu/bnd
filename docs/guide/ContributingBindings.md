# Contributing a Bindings Crate to This Repository

Bindings products in this workspace use a generator crate plus a checked-in
product crate. For standalone use outside this repository, see
[AuthoringBindings.md](AuthoringBindings.md).

Use `bnd-linux-gen`/`bnd-linux` and
`bnd-openssl-gen`/`bnd-openssl` as the production reference designs.

## Architecture

```text
bnd-zstd-gen/                         bnd-zstd/
  Rust header/library policy            checked-in canonical WinMD
  bnd-clang -> per-header RDL            checked-in generated Rust
  windows-rdl -> flat temporary WinMD    generated Cargo features
  metadata remap -> canonical WinMD      native ABI/runtime tests
  bnd-bindgen package mode
                 |
                 +---------------------> regenerated artifacts
```

The scrape metadata uses one flat namespace. The checked-in canonical
metadata, generated Rust modules, and features are organized by the header
that defines each item.

## 1. Create the product crate

The product crate contains hand-written package metadata and crate root plus
generated artifacts:

```text
bnd-zstd/
├── Cargo.toml
├── winmd/
│   └── bnd-zstd.winmd
└── src/
    ├── lib.rs
    └── zstd/
        └── ... generated defining-header modules ...
```

The crate root should expose the package namespace and provide the link macro
alias:

```rust
//! Rust FFI bindings for zstd.
//!
//! Generated by `bnd-zstd-gen`. Do not edit `src/zstd/` manually.

pub mod zstd;

extern crate bnd_macros as windows_link;
```

The manifest needs `bnd-macros` and a stable marker where package mode may
write generated features:

```toml
[dependencies]
bnd-macros.workspace = true

[features]
default = ["zstd"]
# generated features
```

Match the existing product manifests when generated modules require explicit
default features or dependencies on another bindings product.

## 2. Create the generator crate

Generator crates are workspace-only Rust programs:

```text
bnd-zstd-gen/
├── Cargo.toml
├── src/
│   ├── clang.rs
│   ├── lib.rs
│   └── main.rs
└── tests/
    └── clang_up_to_date.rs
```

Use workspace paths for the maintained forks and the repository's selected
`windows-rdl`/`windows-metadata` dependencies. Do not introduce a TOML
header-extraction configuration: header scope, compiler arguments, native
libraries, exclusions, and external-reference routes are generator policy
written in Rust.

## 3. Define header and library policy in Rust

Start with explicit root headers and the complete set of defining headers
that may own emitted declarations:

```rust
const ROOT_HEADERS: &[&str] = &[
    "zstd.h",
];

const PARTITION_HEADERS: &[&str] = &[
    "zstd.h",
    "zstd_errors.h",
];
```

Generate one source string containing all root includes. Parsing one
translation unit gives Clang a coherent type graph:

```rust
let source = ROOT_HEADERS
    .iter()
    .map(|header| format!("#include <{header}>\n"))
    .collect::<String>();

windows_clang::clang()
    .input_text(&source)
    .args(["-x", "c", "-std=gnu11"])
    .namespace("zstd")
    .library("zstd")
    .scope_headers(PARTITION_HEADERS.iter().copied())
    .output(&rdl_dir)
    .write_by_header()
    .expect("bnd-clang failed to generate zstd RDL");
```

Add only policy required by the target API:

- `.arg(...)`/`.args(...)` for target, include, language, and macro flags;
- `.include_macro(...)` for selected public leading-underscore macros;
- `.exclude_symbol(...)` for unavailable declarations;
- `.libraries(...)` for per-symbol native library exceptions;
- `.header_libraries(...)` for defining-header library overrides;
- `.reference(...)` for declarations owned by another canonical WinMD.

These choices belong in the generator so they are reviewed, tested, and
versioned with the generated product.

## 4. Compile the flat intermediate WinMD

Compile the RDL directory into one flat temporary namespace:

```rust
windows_rdl::reader()
    .input(&rdl_dir)
    .reference_default()
    .output(&flat_winmd)
    .write()
    .expect("windows-rdl failed to compile zstd metadata");
```

If another product owns referenced types, pass its canonical WinMD to both
`windows_clang::clang().reference(...)` and
`windows_rdl::reader().reference(...)`.

## 5. Create canonical defining-header metadata

`write_by_header()` emits one RDL file per defining header. Use
`windows_clang::remap_by_header()` to derive item ownership from those files,
structurally remap the flat metadata, and repair external TypeRef scopes:

```rust
windows_clang::remap_by_header()
    .rdl_dir(&rdl_dir)
    .scratch_dir(&temporary_remap_dir)
    .source("zstd")
    .input(&flat_winmd)
    .output(&canonical_winmd)
    .import("Windows::Win32")
    .reference_default()
    .write()
    .expect("failed to remap zstd metadata");
```

Check the canonical result into `bnd-zstd/winmd/bnd-zstd.winmd`. Header stems
are sanitized consistently, including a trailing underscore for Rust
keywords. The RDL round trip is required because the metadata remapper does
not preserve external assembly scopes itself.

## 6. Generate the package

Run the maintained bindgen fork in sys/package mode:

```rust
let mut bindgen = windows_bindgen::Bindgen::new();
bindgen
    .input(&canonical_winmd)
    .output(output_dir)
    .filter("zstd")
    .sys()
    .package()
    .package_feature_root("zstd")
    .write();
```

Package mode writes `src/zstd/**` and generated Cargo feature entries. Preserve
the hand-written manifest prefix and restore it if generation panics; both
production generators protect the product manifest this way.

## 7. Route external references

When the generated API uses types owned by another bindings crate:

1. Reference that crate's canonical WinMD during Clang and RDL generation.
2. Import its namespaces while repairing the remapped local WinMD.
3. Include both canonical WinMD files in bindgen inputs.
4. Exclude external metadata namespaces from local output.
5. Add one namespace-wide `Bindgen::reference()` using
   `ReferenceStyle::Full`.
6. Add the corresponding product dependency and defining-header features.

For example, OpenSSL routes the `libc` namespace to `bnd_linux`; metadata
type `libc.struct_tm.tm` therefore becomes
`bnd_linux::libc::struct_tm::tm`.

See
[`bnd-openssl-gen/src/clang.rs`](../../bnd-openssl-gen/src/clang.rs) and
[CrossWinmdReferences.md](../design/features/CrossWinmdReferences.md).

## 8. Check in generated artifacts

A production bindings change normally updates all of:

- `bnd-zstd/src/zstd/**`;
- `bnd-zstd/winmd/bnd-zstd.winmd`;
- generated features in `bnd-zstd/Cargo.toml`.

Do not hand-edit generated Rust, canonical WinMD, or generated manifest
features. Change generator policy and regenerate.

Add the generator to the repository generation order. If it references
another product WinMD, generate the dependency first.

## 9. Add freshness and determinism tests

The generator test must regenerate into a staging directory and compare:

- the complete generated Rust file set and bytes;
- canonical WinMD bytes;
- the final manifest, including generated features.

Run generation a second time in the same staging directory and assert that
the sources, WinMD, manifest, and file set remain identical.

Use the existing tests as templates:

- [`bnd-linux-gen/tests/clang_up_to_date.rs`](../../bnd-linux-gen/tests/clang_up_to_date.rs)
- [`bnd-openssl-gen/tests/clang_up_to_date.rs`](../../bnd-openssl-gen/tests/clang_up_to_date.rs)

## 10. Add metadata and native tests

Generator tests should verify the contract that matters for the API:

- representative types, constants, callbacks, and method signatures;
- native library ownership;
- canonical defining-header namespaces;
- deterministic structural remapping and reference-scope repair;
- external TypeRefs and namespace-preserving Rust ownership.

Product or integration tests should call the real shared library and verify
ABI-sensitive sizes, alignments, offsets, values, and round trips.

## Regeneration and review

Add a focused generation command and include it in `just generate` in the
correct dependency order. Before submitting a change:

```sh
cargo run -p bnd-zstd-gen
cargo test -p bnd-zstd-gen
cargo test -p bnd-zstd
```

Inspect generated API changes together with canonical WinMD and manifest
changes. Treat an unexplained generated diff as a generator bug or policy
change, not as output to edit manually.
